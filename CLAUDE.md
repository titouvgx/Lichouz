- **Détails à lire seulement si besoin** : `docs/architecture.md` (modèle, Realtime, photos, hors connexion, vie du foyer, structure des fichiers, recettes livrées), `docs/design.md` (design « Brutal beurre » depuis v1.9.0, règles UI mobile), `docs/historique.md` (étapes passées, anciennes décisions), `supabase/prod/README.md` (mise en prod), `tests/rls/README.md` (banc d'attaque)

## Modèle familles (migration 17)
- **Une personne = une famille** (`profiles.family_id`, rôle `admin`/`member`) ; **une famille = une super-famille** (`families.super_family_id`)
- **Super-admin** (`super_admins`) : voit tout, crée les liens « fondateur » (`#/admin`)
- **Fondateur** (`super_families.founder_id`) : crée jusqu'à 3 familles (illimité si super-admin), invite et gère dans toutes ses familles, n'est membre que de la sienne
- **Admin de famille** : invite dans SA famille (membre ou admin), change les rôles (jamais le sien ni celui du fondateur), renomme la famille, retire un membre ; ne renomme pas les autres
- **Retirer** (`remove_member`, migration 19) = supprimer le compte (`auth.users` → profil en cascade, recettes gardées avec auteur NULL, ses liens supprimés) ; jamais soi-même, le fondateur ni un super-admin. **Supprimer une famille** (`delete_family`) : fondateur ou super-admin, famille vide (0 membre, 0 lien en attente), pas la sienne, pas celle du catalogue, aucune recette au planning d'une autre famille. Plus de `DELETE` direct sur `families` / `profiles`
- **Invitations** : lien à usage unique, 7 jours, annulable, **réservable à une adresse e-mail** (v1.7.0, facultatif ; seuls l'empreinte et l'indice « m•••@… » sont gardés ; refus = rien n'est consommé), seul `sha256(jeton)` stocké, 20 en attente max par personne. Compte créé par la fonction serveur `supabase/functions/accepter-invitation` (`createUser` **non confirmé** depuis v1.3.0, puis `consume_invitation`, réservé `service_role` ; compte supprimé si le rattachement échoue). Le site demande ensuite l'e-mail « Confirm signup » (`auth.resend` type `signup`) ; connexion impossible avant le clic (Supabase Auth refuse `email_not_confirmed`, vérifié dans son code) ; « Renvoyer » sur l'écran d'après-création et sur la connexion
- **Recettes** : jamais supprimées depuis l'appli, **archivées** (`archived_at`, admin de la famille ou super-admin ; masquées des listes, gardées dans les plannings ; « Recettes archivées » en bas de Recettes pour restaurer) ; `visibility` = `famille` (défaut) | `super_famille` | `catalogue` (50 recettes livrées, lecture seule sauf super-admin). Planning, listes, habituels, placard : par famille (`is_family`)
- Fonctions SQL : `create_invitation`, `revoke_invitation`, `invitation_info` (anonyme), `consume_invitation`, `create_family`, `remove_member`, `delete_family`, `admin_stats` (super-admin, nombres seulement), `delete_my_account` (migration 21 : soi-même, mot de passe vérifié par `extensions.crypt`, 5 erreurs/15 min → bloqué ; refuse super-admin, fondateur, dernier admin d'une famille avec membres ; essais dans `private.account_deletion_attempts`, schéma jamais exposé) ; aides `can_read_recipe`, `can_edit_recipe`, `can_invite`, `is_founder…` ; gardes `guard_profile_update`, `guard_family_write`, `guard_super_family_update`, `guard_recipe_write` (auteur → NULL permis si son compte n'existe plus), `guard_item_checked_by`, `guard_family_delete`
- API front : `src/lib/api/famille.ts` ; contexte (`family`, `superFamily`, `isFounder`, `isSuperAdmin`) dans `src/lib/profile.svelte.ts`

## Sécurité (OBLIGATOIRE)
- **Jamais de clé secrète** (`sb_secret_…` / service_role) ni mot de passe base dans le dépôt, `.env.local` ou variables GitHub : clé **publishable** seulement (garde-fous dans `vite.config.ts` et `src/lib/supabase.ts`)
- **RLS jamais désactivé**. RLS = lignes ; pour limiter des colonnes → trigger. Sur Supabase, viser `anon` explicitement dans les `REVOKE`
- **E-mail de l'utilisateur** : privé, jamais transmis à l'extérieur sans accord
- Ne pas lancer `npm audit fix --force`. Pas de ressource tierce (polices hébergées avec le site)
- **CSP** (`index.html`) : scripts du site ; connexions `*.supabase.co` et Unsplash seulement. Toute nouvelle source externe → l'ajouter à la CSP
- Actions GitHub épinglées par SHA, permissions minimales
- Droits côté appli = droits de la base ; une suppression filtrée par RLS (0 ligne) est signalée, jamais affichée comme réussie
- En place : `security-check.yml` (un inconnu ne lit rien, après chaque déploiement + lundi), `verifications.yml` (secrets, audit, types, tests, build ; le déploiement en dépend), banc RLS : 1 224 attaques bloquées, 281 contrôles positifs, 22 de structure (v1.999.0, 24 tables) ; journal des erreurs `src/lib/errorReport.ts` (texte nettoyé : ni e-mail, ni jeton, ni paramètres, ni `details` des erreurs Postgres ; un membre ne relit pas le journal → insérer SANS `.select()`)
